# Changelog

Until 0.10.0 the kit's built-in texts (button labels, messages, calendar) and the documentation were in Italian;
quoted UI strings below are translated here. From 0.11.0 on the texts come from a per-language dictionary.

## 0.11.0 — 17 November 2026

- **Languages** (`Kit.i18n`): the texts `kit.js` writes by itself now come from a per-language dictionary, **English** (the default) and **Italian**, chosen from `<html lang>`. **Heads-up, the default behavior changes**: a page without `lang` now gets English texts ("Cancel", "No results"); for Italian you need `<html lang="it">`. `Kit.i18n.lang(code)` sets the language by hand, `Kit.i18n.add(code, dictionary)` adds one (it can hold only what differs: `pt-BR` falls back to `pt`, then to `en`), `Kit.i18n.t(key)` reads an entry; attributes and options (`data-kit-empty`, `{ cancel }`, …) always win. The language also drives the date order (`mm/dd/yyyy` or `dd/mm/yyyy`), the first day of the week in the calendar, the decimal separator used to sort numeric columns, and file sizes. The date-range presets now have English names (`today`, `yesterday`, `month`, `last-month`, `year`, `last-year`); the old Italian names still work, and `data-kit-disable` recognizes weekday names in every loaded language. New "Languages" section on the JavaScript page.
- Documentation in two languages: the pages are now `docs/en/*.html` and `docs/it/*.html` (sources in `docs/src/en|it/`), with a language link in the header and a search index per language; `docs/index.html` redirects by browser language. **Addresses change**: `docs/forms.html` becomes `docs/it/forms.html` (or `docs/en/…`). Every page is available in both languages; the two example dashboards are `docs/en/dashboard*.html` and `docs/it/dashboard*.html` (the old `docs/dashboard*.html` addresses are gone). The VS Code snippets are now in English.
- For tools and agents: `llms.txt` (index), `llms-full.txt` (the English documentation as Markdown) and `kit-components.json` (classes, attributes and functions used in each section) are generated by `tools/gen-docs.py`; `AGENTS.md` has the rules for working on the repository.
- README and this changelog are now in English (`README.it.md` is the Italian README).

## 0.10.0 — 17 November 2026

- Meter (`kit-meter`): a measurement against a limit (disk used, quota, score). It differs from the progress bar because the color tells the level: `is-success`, `is-warning`, `is-danger` (accent color by default), `kit-meter-sm|lg`, and `kit-meter-head` for a name and value above the bar. CSS only for server-side rendering, with `role="meter"` and `aria-value*`. With `data-kit-meter` (`data-kit-value`, `-min`, `-max`, `-warn`, `-danger`, `-good="high"` for scores) `kit.js` writes the width, ARIA and color, also on htmx fragments. `Kit.meter(element, options)` returns `{ set, value, state }`. Snippet `kit-meter`. New "Meter" section on the Feedback page.
- Dialog: long content now scrolls even when the header, body and footer are wrapped in a `<form>` (the body used to grow past the window and push the footer out of view) and when the content is placed in the dialog without `kit-card-body` (the whole dialog scrolls). The maximum height uses `dvh`, so on a phone it no longer ends up under the browser bar.

## 0.9.0 — 12 November 2026

- Sortable table (`data-kit-sort` on `kit-table`): headers become buttons that sort ascending, descending and then back to the original order, with `aria-sort` and an arrow. The column type is recognized from its content: numbers in Italian format (`1.250,00`, `−310,00`, `12 %`, `€ 5`), dates (`12/03/2026`, `2026-03-12`, with time) and text compared without regard to case and accents and with "natural" numbers (`FT-9` before `FT-10`). Empty cells go last, ties keep the original order. `data-kit-type="num|date|text"` and `data-kit-nosort` on headers, `data-kit-value` on cells, `aria-sort` written in the HTML as the initial order. With `data-kit-sort="multi"` you can sort by several columns: Shift or Ctrl/⌘ + click (from the keyboard Shift + Enter) adds the column as the next criterion, reverses it and then removes it; a plain click starts again from that column alone. With several criteria the priority (1, 2, 3…) appears next to the arrow. From code, `api.sort([[2, "ascending"], [3, "descending"]])`. `kit:sort` event with `{ column, direction, criteria }` (`column` and `direction` are those of the first criterion).
- Text filter (`data-kit-filter="#table"` on a field): only the rows containing all the typed words remain, ignoring case and accents; a "No results" row (`data-kit-empty`) when nothing is left. `kit:filter` event with `{ query, count }`.
- Pagination (`data-kit-page="N"` on `kit-table`, `Kit.paginate(table, rows)`): the `kit-pagination` bar with a count ("1–10 of 47", `aria-live` area), previous and next, and page numbers with ellipses, `aria-current="page"`, and focus that stays on the pressed button. It works together with sorting and filtering (the count is that of the filtered rows). `kit-pagination` can be written by hand for server-side pagination. `kit:page` event with `{ page, pages, size, total }`. The bar is not printed.
- `Kit.table(table, { sort, size, filter, page, empty, labels })` returns `{ sort(), filter(), page(), pageSize(), refresh(), state() }`; call `refresh()` after changing the rows from code. Snippet `kit-table-sort`. New "Sorting", "Text filter", "Pagination" and "JavaScript" sections on the Tables page.
- htmx: fragments inserted by htmx initialize themselves (`kit.js` listens to `htmx:load` and calls `Kit.init` on the container, once even if many nodes are inserted): selects, comboboxes, tabs, highlighted code and sortable tables inside the response work with nothing else. For server-side pagination, sorting and filtering (Django + htmx) use CSS only: `kit-pagination`, `kit-sort-btn` (also on an `<a>`, without underline) with `aria-sort` and `kit-sort-n` for the priority, and `kit-table-empty` for "No results". New "With Django and htmx" section on the Tables page, with a template, a view (`Paginator`, `{% querystring %}`, browser history, focus after the swap) and a loading indicator.
- Sticky header and columns in tables: `kit-table-scroll` on the wrapper (`kit-table-wrap`) gives it a maximum height (`--kit-table-h`, `28rem` by default) and makes it scroll vertically too, with the header stuck to its top edge (before, the wrapper only scrolled horizontally, so the header never detached). `kit-table-fix` pins the first column on the left during horizontal scrolling, with CSS only and also on rows added later; `data-kit-fix="2|3|4"` pins more, with widths measured by `kit.js` (re-measured when the table resizes) or written by hand in `--kit-fix-1|2|3`. The corner cell sits above everything, highlighted and selected rows cover the pinned column, and a thin line on the right marks where the last pinned column ends; when printing, the maximum height and the pinning do not apply.
- Accordion (`kit-accordion`): a list of collapsible sections built on the native `<details>`, so it also works without JavaScript and from the keyboard. Title in the `<summary>`, content in `kit-accordion-body`, `kit-accordion-meta` for a count or a badge on the right, `kit-accordion-flush` without a frame for use inside a card. A rotating arrow and animated opening where the browser allows (not with "reduce motion"); all items are open when printing. `data-kit-accordion="single"` keeps only one item open (if several start open, the first stays; without JavaScript the same `name` on the `<details>` is enough). `Kit.accordion(element, { single })` returns `{ open, close, toggle, openAll, closeAll, items }`, `kit:accordion` event with `{ item, index, open }`. Snippet `kit-accordion`. New "Accordion" section on the Content page.
- Breadcrumb (`kit-breadcrumb`): CSS-only navigation path, with `<nav aria-label>`, `<ol>` and `aria-current="page"` on the last item. The separator is drawn by CSS (a small arrow, or a slash with `kit-breadcrumb-slash`), so a screen reader reads only the names; an icon before the text aligns itself; links have hover, visible focus and a highlighted current item. Below 576px `kit-breadcrumb-collapse` keeps only the first and last items on one row, with a `kit-breadcrumb-more` ("…") item in place of the others. Snippet `kit-breadcrumb`. New "Breadcrumb" section on the Navigation page.
- Dates and times. The `date`, `time`, `datetime-local`, `month` and `week` fields with `.kit-input` look like the other fields (also on iOS: left-aligned text, correct height when empty, aligned numbers). `kit-daterange` puts two fields in a single frame, also without JavaScript.
- Optional calendar (`data-kit-datepicker` on an `<input type="date|datetime-local|time">`, `data-kit-timepicker` for time): the field shows and accepts `dd/mm/yyyy` (you can also type `5/3/26`, `05032026`, `2026-03-05`, with the slashes added automatically), while the submitted value is always ISO, in a hidden field that takes the `name` (so Django reads it without formats and the form resets with `reset`). Without JavaScript the native field stays. The calendar has Italian month names, a week starting on Monday, today highlighted, a month title to pick month and year (birth dates), `min` and `max` (ISO, `today`, `+30`, `-7`), `data-kit-disable="sat,sun,2026-12-25"` or a function, "Today" and "Clear" (absent if `required`); validation with `setCustomValidity` and `aria-invalid`. Full keyboard support (arrows, Home/End, PageUp/PageDown, Shift for the year, Esc, down arrow from the field).
- Range (`data-kit-daterange` on a container with two date fields): two months side by side with the band between the dates and a preview while choosing the end, quick choices (`data-kit-presets`: `today`, `yesterday`, `7`, `30`, `90`, `month`, `last-month`, `year`, `last-year`, trimmed by `min` and `max`), and a check that the end does not precede the start. Date and time (`type="datetime-local"`): a calendar with hour and minute columns (`data-kit-step` or `step`) and "Done". Time (`type="time"`): two columns, you can also type `9`, `9.30`, `930`.
- Phone: below 576px the calendar is a bottom sheet with a darkened backdrop, a "Close" button and a frozen page; with a "coarse" pointer the cells are 44px; the field does not open the keyboard (`inputmode="none"`) and is at least 16px (no iOS zoom). The popup is in the top layer (`popover`): no container clips it, dialogs included, where Esc closes only the calendar. `input`, `change` events (also for `hx-trigger="change"` on the form) and `kit:change` with `{ value, display }` or `{ from, to }`. `Kit.datepicker`, `Kit.daterange`, `Kit.date.parse/format/today/labels`. Snippets `kit-date`, `kit-daterange`, `kit-datetime`, `kit-time`. New "Dates and times" page.
- Forms: layout and states (new "Forms: layout and validation" page). `kit-label` labels with `kit-required` and `kit-optional`, `kit-hint` help text, `kit-counter` counter (with `data-kit-count="#field"`, uses `maxlength`). Layout: `kit-form` as a column, `kit-form-h` / `kit-field-h` with the label on the left (`--kit-label-w`, stacked below 576px), `kit-form-inline`, `kit-form-section` (title and fields side by side), `kit-fieldset`, and the existing `kit-row` / `kit-col-*` grid. States `is-valid`, `is-invalid`, `is-warning` on a field, `.kit-field` or group (they apply to inputs, kit selects, comboboxes, files, the drop zone, the date range, checkboxes and cards), `aria-invalid="true"` equals `is-invalid`; messages `kit-feedback-valid|invalid|warning`; `kit-validate` for CSS only with `:user-invalid`.
- Validation (`data-kit-validate` on a `<form>`, `Kit.validate(form)`): checks the HTML rules on submit, marks `is-invalid`, writes the message into `.kit-feedback-invalid` (creating it if missing), links `aria-describedby`, moves focus to the first error and blocks submission (htmx included); the error disappears as soon as the value is correct and a field turns red on blur only if the user typed in it; `="ok"` also marks `is-valid`. Custom messages with `data-kit-msg` and `data-kit-msg-required|type|pattern|min|max|minlength|maxlength|step`. Works with the calendar, kit selects, checkboxes, radios and files. `kit:invalid` event, `Kit.validate.reset(form)` (also on the form's `reset`).
- Fields: sizes `kit-input-sm|lg`, `kit-field-sm|lg`, `kit-form-sm|lg`, `kit-input-group-sm|lg`, `kit-btn-sm`; icons inside the field with `kit-control` (`kit-control-start`, `kit-control-end`) and a result icon drawn by CSS (no images); `data-kit-password` to show and hide the password; `kit-input-group` groups with `kit-input-text`; a floating label `kit-float`; checkboxes with an explanation `kit-check-text`, `kit-check-group` / `kit-check-inline` groups and `kit-check-card` / `kit-check-cards` cards; textarea, native select with an arrow drawn by CSS, file, color, `kit-range`, read-only, disabled and `kit-input-plain`. Snippets `kit-form`, `kit-field`, `kit-form-h`, `kit-input-group`, `kit-control`, `kit-float`, `kit-check-cards`.
- The last visible row of a filtered or paginated table is marked with `is-last` (no line below, card corners and spacing as before).
- Documentation reorganized by topic: the menu is in groups (Foundations, Forms, Navigation, Data, Feedback and overlays); forms are on four pages (basic fields, layout and validation, select and file, dates and times); the "Content" page is gone (key/value and code are in "Cards and details", the legend in "Charts", the welcome screen in "Alerts and progress", and the accordion has its own page). Addresses change: `forms.html#select`, `#file`, `#dropzone` and `#combobox` are now in `form-controls.html`.

## 0.8.0 — 11 November 2026

Parts `kit-sidebar-head` (logo), `kit-sidebar-body` (items, scrolls by itself) and `kit-sidebar-foot` (utilities and account at the bottom); `kit-side-link` items (`aria-current`, `aria-disabled`, badge), `kit-side-title` groups, sub-items with `<details class="kit-side-details">` and `kit-side-sub`, `kit-side-user` / `kit-side-avatar` account with an upward menu. - Fixed: in print, the selector for `.kit-header`, `.kit-toasts`, `.kit-tabs` and the other elements to hide had a double comma, so the browser discarded the whole rule and they were not hidden.

## 0.7.0 — 11 November 2026

- Select from a native `<select>`: `data-kit-select` on a `<select>` (or `Kit.select(el, { search, empty, placeholder })`) hides it and puts the kit's button and menu next to it. The `<select>` stays the data source (`value`, form, `required`, `change` event; `kit:change` with `{ value, label }` also fires). `<optgroup>` for groups, `data-kit-hint` for the second line, `data-kit-short` for a shorter text on the button, and a search field from 21 items up (`data-kit-search="N|off"`). Changing the options or `disabled` updates the button by itself; after a `select.value = …` from code, call `api.sync()`. `Kit.select` returns `{ sync, open, close }`. The menu moves to the left if it would leave the screen.
- A menu's search field accepts the space key; Tab closes a menu with search.

## 0.6.0 — 10 November 2026

- Code snippets (`data-kit-code` on `<pre class="kit-code">`): HTML (including `<script>` and `<style>`), JavaScript and CSS code is colored as in an editor, in light and dark themes; without the language it guesses. With `data-kit-code-copy` a "Copy" button appears (`kit-snippet`, `kit:copy` event). `Kit.code(pre, { lang, text, copy })` and `Kit.highlight(text, language)`: they build only text nodes and `<span>`s, never HTML; linear time even with hostile texts and, above 100,000 characters, the text is left uncolored. Tokens `--kit-hl-tag|attr|str|kw|fn|num|com`. Snippet `kit-code`. The documentation uses it for all its examples.
- Documentation: search in the header (the "/" key or Ctrl/⌘ K). It searches titles, text and names of classes, attributes, tokens and functions (`kit-list`, `data-kit-split`, `--kit-accent`, `Kit.progress`), ignoring accents; every typed word must appear. It is a kit combobox, with an index generated by `tools/gen-docs.py` (`docs/search-index.js`).
- Switch (`kit-switch`): an `<input type="checkbox" role="switch">` with on/off graphics; `kit-switch-between` for settings in a list.
- Spinner (`kit-spinner`, `-sm`, `-lg`, `-accent`) and skeleton (`kit-skeleton` with `-text`, `-title`, `-circle`, `-block`): loading indicators, still with "reduce motion". Snippets `kit-switch` and `kit-skeleton`.
- Print: the kit always prints on light, without header, alerts, tabs and shadows, with badge and chart colors; cards, lists, KPIs and table rows do not split and the table header repeats. New classes `kit-no-print`, `kit-print-only`, `kit-print-break` and `kit-print-avoid`.
- List (`kit-list`, `kit-list-item`): items stacked in the same frame, like joined cards. Items can be `<li>`, `<a>`, `<button>` or `<div>`; links and buttons highlight on hover, `is-active` / `aria-current` marks the chosen item, `aria-disabled` the unavailable one. `kit-list-main` part (title + description), states `kit-list-item-success|warning|danger`, variants `kit-list-numbered`, `kit-list-horizontal`, `kit-list-cards` (items as separate cards), `kit-list-sm` (compact) and `kit-list-flush` (no frame, for lists inside a card). Snippet `kit-list`.
- File field (`kit-file`, `data-kit-file`) and drop zone (`kit-dropzone`): button, file name and "×"; type (`accept`) and size (`data-kit-file-max`, in MB) checks, an error below the field, and the files also stay in the form's field. The zone works from the keyboard, accepts folders read in full (`data-kit-file-dir`, files of other types are ignored) and, with `data-kit-file-page`, files dropped anywhere on the page (with a veil while dragging). `kit:files` event with `{ files, items, rejected }`; `Kit.file(el, options)`.
- Full-screen progress: `Kit.progress(text, { value, delay, onCancel })` returns `{ update, close }`. Without a value the bar runs by itself (`kit-progress-indeterminate`); Esc and a click on the backdrop do not close it, unless there is `onCancel`.
- Drawer: `<dialog class="kit-dialog kit-drawer">` slides in from the window edge (right by default; `kit-drawer-left|top|bottom`, width `--kit-drawer-w` or `kit-drawer-sm|lg|xl`, height `--kit-drawer-h`). The same attributes, Esc and backdrop as the dialog.
- Side panel (`kit-split`) with JavaScript: `data-kit-split-open`, `data-kit-split-close` and `data-kit-split-full` (full width), `data-kit-split` for Esc, `Kit.split(el)` and the `kit:split` event. Focus goes to the panel and returns to whoever opened it. Below 900px the panel enters from the right with a dark veil behind it (click to close it; width `--kit-split-overlay-w`, 860px) instead of covering the whole page; `kit-split-lg` does it already below 1250px. New parts `kit-split-head`, `kit-split-title`, `kit-split-body`.
- Combobox (`kit-combo`, `data-kit-combo`, `Kit.combo(el, { items, max, empty, more, filter, autoActive })`): a text field with a suggestion list that narrows as you type. Items written in the HTML or given from JavaScript (strings or `{ value, label, hint }`, array or function), a limit on shown items with a prompt to keep typing, arrows/Enter/Esc/Tab, `role="combobox"` and `aria-activedescendant`. You can also type a value outside the list. `kit:change` event with `{ value, label }`.
- Charts in SVG, without libraries: `Kit.barChart` (also stacked with `stacked`), `Kit.lineChart` (`null` values = gap, `area`, `zero`, different symbols per series), `Kit.donut` (donut with legend) and `Kit.sparkline` (tiny bars or line for KPI cards). Bars and lines: SVG with a round-value axis (k and M), one or more series with a legend, group labels (for example the year), horizontal scrolling starting from the last bar, tooltip, keyboard-clickable bars (`onSelect`, `kit:select` event), redraw when the width and text size change. New tokens `--kit-c3` and `--kit-c4`. New "Charts" page in the documentation.

## 0.4.0 — 10 November 2026

- Settings panel (`kit-settings`): a popover with theme, text size and width, which stays open after each choice; `data-kit-reset` and `Kit.reset()` restore the starting values (`kit:reset` event). It replaces the "Theme" and "Text" menus on the documentation pages and in the sample dashboard.

- Thin scrollbars in the theme colors, brought over from Fatture Elettroniche Explorer: `--kit-sb` token, applied to all elements; `kit-no-scrollbar` hides the bar of a scrolling element.

The dark theme does not change. Whoever overrode these tokens is not affected.
- Fixed: zero was not slashed in code blocks (`kit-code`) and in toasts, because the `font:` shorthand resets `font-variant-numeric`.
- Fixed: tooltips (`data-kit-tip`) stayed on the page as transparent elements and, near the edge, made horizontal scroll appear on phones; at rest they are now `display: none` (with the `display` transition, `allow-discrete`: in Firefox 120–128 they appear without a fade).
- Navbar: `kit-navbar` on the header, with `kit-brand`, `kit-nav` and `kit-nav-link` for items (current with `aria-current`, also disabled or with an icon and badge), dropdown items (`kit-dropdown` inside the `<li>`), `kit-navbar-menu` and `kit-navbar-toggler` (`data-kit-nav="#id"`) for the collapsible menu, `kit-navbar-actions` for what always stays visible, `kit-navbar-expand-sm|md|lg|xl` for the point from which the menu is inline, `kit-nav-col` for the vertical list. - Toast: the limit of simultaneous toasts goes from 4 to 6, and at the bottom of every toast with a duration a bar appears that shortens until it closes (`kit-toast-bar`; `progress: false` removes it). When the mouse or focus pauses the timer, the bar goes back to full and restarts together with the count.
- Confirmations: `Kit.confirm(question, { text, confirm, cancel, danger, type })` opens a confirmation dialog (`role="alertdialog"`) and returns a `true`/`false` promise; with `danger` the button is red (`kit-btn-danger-solid`) and focus starts on "Cancel"; with `type` you must type a text to enable confirmation. `data-kit-confirm` (+ `-text`, `-ok`, `-cancel`, `-danger`, `-type`) does the same on buttons, links and forms without JavaScript, before your click handlers. `Kit.undo(text, { onUndo, onCommit })` runs the action right away and offers "Undo" in a toast; `onCommit` fires if it is not undone. `Kit.toast` accepts `onClose`. New "Asking for confirmation" section in "Dialogs and menus".
- Dialog animation: appearing and disappearing with a fade, a slight slide and a backdrop that darkens (0.18 s, disabled with `prefers-reduced-motion`; needs Chrome 117, Safari 17.4 or Firefox 129, no animation elsewhere).
- `a.kit-brand` no longer has an underline or the link color.
- The chip's × is more readable (a lighter background and, on mouse hover, text in the `--kit-accent-ink` color).
- Documentation: the dashboard chart scrolls horizontally below 600px instead of shrinking the labels (now 12px), and inline code wraps.
- New `text` icon; the documentation pages have a "Text" menu.

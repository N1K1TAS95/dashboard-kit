Ordinamento

Con kit.js, data-kit-sort sulla tabella rende cliccabili le intestazioni: il primo clic ordina in modo crescente, il secondo decrescente, il terzo riporta l'ordine di partenza. L'intestazione riceve aria-sort (ascending, descending, none) e dentro si mette un bottone, quindi funziona anche da tastiera. Il tipo della colonna si riconosce dal contenuto: numeri in formato italiano (1.250,00, −310,00, 12 %, € 5), date (12/03/2026, 2026-03-12, con l'ora se c'è) e testo, confrontato senza badare a maiuscole e accenti e con i numeri «naturali» (FT-9 prima di FT-10). Le celle vuote o con solo un trattino vanno sempre in fondo; a parità di valore resta l'ordine di partenza. Un aria-sort="ascending|descending" scritto nell'HTML è l'ordinamento iniziale.

Più colonne

Con data-kit-sort="multi" si ordina anche per più colonne insieme: Shift + clic o Ctrl/⌘ + clic sull'intestazione la aggiunge come criterio successivo (e di nuovo la inverte, e poi la toglie), mentre un clic normale riparte da quella colonna sola. Il primo criterio è quello principale, gli altri decidono a parità; con più criteri accanto alla freccia compare il numero di priorità. Da tastiera, Shift + Invio sul bottone dell'intestazione. Provalo: Cliente, poi Shift + clic su Importo.

Con Kit.table si ordina anche da codice (api.sort(2, "descending"), oppure api.sort([[2, "ascending"], [3, "descending"]]) con multi) e arriva l'evento kit:sort con { column, direction, criteria } (column e direction sono quelli del primo criterio, criteria li elenca tutti); vedi l'API.

Filtro di testo

data-kit-filter="#id" su un campo di testo collega il campo alla tabella con quell'id: mentre si scrive restano le righe che contengono tutte le parole (in qualsiasi cella, senza badare a maiuscole e accenti). Se non resta nulla compare una riga «Nessun risultato» (data-kit-empty sulla tabella per cambiare il testo). L'ordine e il filtro lavorano insieme; l'evento è kit:filter con { query, count }.

Paginazione

data-kit-page="N" sulla tabella mostra N righe per volta e aggiunge sotto la barra kit-pagination: il conteggio («1–5 di 12»), i pulsanti precedente e successivo e i numeri di pagina con i puntini quando sono tanti. La pagina corrente ha aria-current="page", il conteggio è un'area aria-live e il focus resta sul bottone premuto. Funziona insieme a ordine e filtro: cambiando uno dei due si torna alla prima pagina, e il conteggio è quello delle righe filtrate. In stampa la barra non c'è e esce la pagina mostrata.

Con Django e htmx

Quando i record sono tanti la paginazione, l'ordine e il filtro li fa il server, una pagina per volta, e data-kit-sort, data-kit-filter e data-kit-page non servono: lavorano sulle righe già presenti. Si usa solo il CSS (kit-pagination, kit-sort-btn, aria-sort) e htmx sostituisce il blocco. Se kit.js c'è, i frammenti inseriti da htmx si inizializzano da soli (evento htmx:load): select, combobox, tab, codice colorato e tabelle ordinabili dentro la risposta funzionano senza chiamare Kit.init.

Lo schema: un contenitore con un id (#fatture) che è il hx-target e contiene la card con tabella e barra; il campo di ricerca sta fuori, così non viene sostituito e il cursore resta dov'è. hx-boost sul contenitore trasforma i link normali (intestazioni, pagine) in richieste htmx con la cronologia del browser; i link continuano a funzionare anche senza JavaScript.

La pagina intera (fatture/elenco.html) contiene il campo e il contenitore; la vista risponde col solo frammento (fatture/_tabella.html) alle richieste htmx.

# fatture/views.py
from django.core.paginator import Paginator
from django.db.models import Q
from django.shortcuts import render

ORDINI = {"data": "data", "cliente": "cliente__nome", "importo": "importo"}

def fatture(request):
    qs = Fattura.objects.select_related("cliente")
    q = request.GET.get("q", "").strip()
    if q:
        qs = qs.filter(Q(numero__icontains=q) | Q(cliente__nome__icontains=q))
    sort = request.GET.get("sort", "-data")
    campo = ORDINI.get(sort.lstrip("-"))
    if campo:
        qs = qs.order_by(("-" if sort.startswith("-") else "") + campo, "pk")   # "pk" tiene stabile l'ordine tra una pagina e l'altra
    page = Paginator(qs, 10).get_page(request.GET.get("page"))
    pages = list(page.paginator.get_elided_page_range(page.number, on_each_side=1, on_ends=1))
    # htmx chiede il frammento, ma il tasto «indietro» senza cronologia in cache vuole la pagina intera
    parziale = request.headers.get("HX-Request") and not request.headers.get("HX-History-Restore-Request")
    return render(request, "fatture/_tabella.html" if parziale else "fatture/elenco.html",
                  {"page": page, "pages": pages, "q": q, "sort": sort})
/* mentre la richiesta è in corso htmx mette .htmx-request sull'elemento di hx-indicator */
#fatture.htmx-request { opacity: .55; pointer-events: none; transition: opacity .2s; }

Qualche dettaglio che conta: {% querystring %} (Django 5.1) tiene gli altri parametri dell'indirizzo, quindi la ricerca e l'ordine restano mentre si cambia pagina, e page=None toglie la pagina quando cambia l'ordine; prima di 5.1 serve un template tag equivalente. Gli id sui link precedente e successivo servono a htmx, che dopo la sostituzione rimette il focus sull'elemento con lo stesso id: chi naviga da tastiera non lo perde. Per le intestazioni, kit-sort-btn funziona anche su un <a>; con l'ordinamento su più colonne scritto dal server il numero di priorità è un <span class="kit-sort-n">2</span> dentro il link.

JavaScript

Gli attributi bastano nella maggior parte dei casi. Se le righe cambiano dopo il caricamento (una tabella riempita da una richiesta) si chiama api.refresh(); per il resto Kit.table(tabella, opzioni) fa tutto da codice e Kit.paginate(tabella, righe) è la scorciatoia per la sola paginazione. Entrambe restituiscono lo stesso oggetto.

const api = Kit.table("#fatture", { sort: true, size: 10, empty: "Nessuna fattura" });

api.sort(3, "descending");   // colonna (da 0) e direzione: "ascending", "descending" o "none"
api.sort([[2, "ascending"], [3, "descending"]]);   // più colonne (con data-kit-sort="multi")
api.filter("alfa");          // come scrivere nel campo di ricerca
api.page(2);                 // vai alla pagina 2; api.page() la legge
api.pageSize(25);            // righe per pagina; 0 = tutte
api.refresh();               // dopo aver aggiunto, tolto o cambiato delle righe
api.state();                 // { sort: { column, direction, criteria }, query, page, pages, size, total, count }

document.querySelector("#fatture").addEventListener("kit:page", (e) => {
  console.log(e.detail);     // { page, pages, size, total }
});

Intestazione e colonne fisse

Di base le intestazioni (<th>) restano incollate sotto .kit-header mentre la pagina scorre. Dentro kit-table-wrap il riquadro scorre solo in orizzontale, quindi l'intestazione non ha niente da cui staccarsi. Per una tabella lunga si aggiunge kit-table-scroll al riquadro: ha un'altezza massima (--kit-table-h, di base 28rem), scorre anche in verticale e l'intestazione resta agganciata al suo bordo superiore. La spaziatura delle celle si regola con --kit-row (verticale) e --kit-cell (orizzontale).

kit-table-fix sulla tabella blocca a sinistra la prima colonna mentre si scorre in orizzontale. Funziona solo con il CSS, anche sulle righe aggiunte dopo (per esempio da htmx), e va d'accordo con riga evidenziata e selezionata. La cella d'angolo (intestazione della colonna fissa) resta sopra a tutto. Prova a scorrere la tabella da un lato e dall'altro.

Cards and details

Cards, KPI cards, stats row, lists, key/value pairs and code blocks: the containers and details of a dashboard.

Card

A container with a border, rounded corners and a light shadow (in the dark theme the shadow disappears). Every part is optional: kit-card-head, kit-card-body, kit-card-foot.

Card title
The card content.

Without kit-card-body the content touches the edges: fine for full-width tables and charts.

List

Items stacked in the same box, like several joined cards: kit-list on the container, kit-list-item on each item. The container can be <ul>, <ol> or <div>; the items <li>, <a>, <button> or <div>. A badge or an icon inside the item aligns by itself; kit-list-main gathers title and description and takes the free space.

Clickable items

With <a> or <button> the item highlights on mouse hover. is-active (or aria-current) marks the selected one, aria-disabled="true" the unavailable one. The container, in this case, is a <div>.

Separate cards and compact

kit-list-cards separates the items: each becomes a card with its own border, with a gap in between. It also works with clickable and active items and with the states. kit-list-sm reduces the space above and below each item and combines with the other variants.

Numbered, horizontal, borderless

kit-list-numbered puts a number in front of each item. kit-list-horizontal lays them out in a row, of equal width (below 760px they stack again). kit-list-flush removes border, corners and shadow: it is for use inside a card, which already has its own box.

Code snippets

A code block colored like in an editor: tags, attributes, strings, keywords, functions and comments. You write a normal <pre class="kit-code"> and with data-kit-code (with kit.js) the code colors itself. The value is the language: html (also with <script> and <style> inside), js or css; without it, kit.js guesses. The text must be written with entities (&lt; instead of <), as in any HTML page. Without kit.js the block stays readable, just without colors.

<button class="kit-btn kit-btn-primary" data-kit-open="#new">
  <svg class="kit-icon"><use href="#i-plus"/></svg> New invoice
</button>
// reload the documents and show the outcome
const n = await loadDocuments({ year: 2026, max: 50 });
Kit.toast(n + " documents", { type: "success" });
.invoice:hover { background: var(--kit-hover); }
@media (max-width: 760px) { .invoice { padding: 8px; } }

The "Copy" button

With data-kit-code-copy the block is put in a kit-snippet and the "Copy" button appears (on mouse hover, always visible on the phone). The attribute's value is the label; data-kit-code-copied is the one that appears after copying. When the text is copied the kit:copy event fires with { text }.

From JavaScript

Kit.code(pre, { lang, text, copy }) colors a block and returns { set(text, lang), text() }, useful when the code changes (a generated example, a preview). Kit.highlight(text, lang) instead returns an already colored DOM fragment, to insert wherever you like. Both build only text nodes and <span>s, never HTML: the displayed code is not executed, whatever it contains. Beyond 100,000 characters the text stays uncolored, so a huge text does not slow the page; an unknown language is guessed.

const block = Kit.code("#example", { lang: "js", copy: true });
block.set("Kit.toast('Saved!');");              // changes the displayed code
element.append(Kit.highlight("<b>hello</b>", "html"));

The colors are the tokens --kit-hl-tag, -attr, -str, -kw, -fn, -num e -com (see Themes and tokens), and change by themselves between light and dark theme.

JavaScript

JavaScript is optional. Without kit.js all the styling works; you only need it for the parts that move: theme, tabs, select, menus, dialogs and toasts.

Principles

  • No dependencies and no build step: a single file, dist/kit.js.
  • It is activated with data-kit-* attributes, without writing code.
  • It uses no innerHTML, eval or inline scripts: it works with script-src 'self'.
  • Handlers are delegated to the document, so they also apply to HTML added after load.

API

Kit.toast("Saved!");            // temporary message; options: type, title, duration, position, action, progress (see Dialogs and menus)
Kit.toast.clear();              // closes all toasts
await Kit.confirm("Delete?", { danger: true });      // confirmation dialog → true / false (options: text, confirm, cancel, danger, type)
Kit.undo("Deleted", { onUndo, onCommit });           // the action happens now, with an "Undo" toast; onCommit if it is not undone
Kit.theme.get();                // "auto" | "light" | "dark"
Kit.theme.set("dark");          // sets and saves the theme
Kit.fontSize.get();             // "sm" | "md" | "lg" | "xl"
Kit.fontSize.set("lg");         // sets and saves the text size
Kit.fontSize.step(1);           // one step larger (-1: smaller)
Kit.reset();                    // restores theme, text and width
Kit.layout.get();               // "boxed" | "fluid"
Kit.layout.set("fluid");        // full-width content (remembered)
Kit.layout.toggle();            // switches
Kit.table("#table", { sort: true, size: 10 });     // sorting, filter and pages of a table (see Tables); Kit.paginate("#table", 10) for pages only
Kit.datepicker("#due");         // calendar on a date, date-time or time field (see Dates and times); Kit.daterange("#period") for the range
Kit.validate("#form");          // checks a form (true/false) and marks its fields; Kit.validate.reset(form) clears states and messages
Kit.date.parse("3/5/26");       // "2026-03-05" (Kit.date.format, Kit.date.today); the day/month order depends on the language
Kit.i18n.lang("en");            // language of the kit's texts (see Languages)
Kit.init(element);              // re-reads selects and tabs in an area added after load

Languages

The texts kit.js writes by itself (the "Cancel" and "Confirm" buttons, labels for screen readers, "No results", table pages, the calendar) come from a dictionary per language. English (the base language) and Italian are built in. The language is the one in <html lang="…">: without the attribute English is used, so on an Italian page remember to write <html lang="it">.

With a language that has a region (pt-BR) it looks for that first, then the language without the region (pt), then English: a dictionary can contain only what changes. Attributes and options (data-kit-empty, Kit.confirm(…, { cancel })) always win over the dictionary.

The calendar and the tables follow the language too: the date order (mm/dd/yyyy in English, dd/mm/yyyy in Italian), the first day of the week (Sunday in English, Monday in Italian), month and day names, and the decimal separator used to sort the numbers in a column (1,250.50 or 1.250,50). The submitted value is always ISO.

Kit.i18n.lang();                 // "en": the language in use (from <html lang>)
Kit.i18n.lang("de");             // sets it by hand, ignoring <html lang>; Kit.i18n.lang("") goes back to <html lang>

// Another language: just write what you need, the rest stays in English
Kit.i18n.add("de", {
    cancel: "Abbrechen", confirm: "Bestätigen", close: "Schließen", noResults: "Keine Ergebnisse",
    num: { dec: "," },
    date: { order: "dmy", first: 1, months: ["Januar", /* … */], days: ["mo", "di", /* … */], t: { today: "Heute", clear: "Löschen" } }
});

// A regional variant: British English writes the day before the month and starts the week on Monday
Kit.i18n.add("en-GB", { date: { order: "dmy", first: 1 } });

The keys are in the dictionary at the top of dist/kit.js (I18N): en is the complete model. Kit.i18n.t("cancel") reads an entry in the current language. Languages must be added before the page builds the components: put Kit.i18n.add(…) right after kit.js.

Events

They are CustomEvents that bubble up the DOM: listen on the document or on the element.

EventOndetail
kit:change.kit-select{ value }: the chosen data-value (for a native select also label)
kit:sort, kit:filter, kit:page<table>{ column, direction }, { query, count }, { page, pages, size, total }
kit:changedate, time or range field{ value, display } (ISO and the field's text) or { from, to }
kit:invalid<form data-kit-validate>{ fields }: the fields that are invalid at submit time
kit:tab.kit-tabs{ tab }: the activated tab element
kit:theme<html>the theme that was set
kit:fs<html>the text size that was set (sm, md, lg or xl)
kit:reset<html>the settings were restored
kit:layout<html>the width that was set (boxed or fluid)
 
document.addEventListener("kit:change", (e) => {
  console.log("Chosen:", e.detail.value);
});

Keyboard

  • Open menus and selects: up/down arrows to move through the items, Enter or Space to choose, Esc to close (focus returns to the button).
  • Tabs: left/right arrows move to the neighboring tab.
  • Dialog: Esc closes it (native behavior); so does a click on the backdrop.

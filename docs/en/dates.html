Dates and times

Date and time fields with the kit's look, an optional calendar for a date, a range, date and time, and time only. Designed for the phone: on narrow screens the calendar slides up from the bottom, with 44-pixel targets.

Native fields

.kit-input also works on date, time, datetime-local, month and week: the same height, border and focus ring as the other fields, aligned numbers and, on iOS, left-aligned text and the right height even when the field is empty. No JavaScript is needed: the picker is the browser's, which on a phone is usually the best. Min and max (min, max) and aria-invalid="true" work as for the other fields.

For a range without JavaScript a kit-daterange container with two fields is enough: they sit in a single frame, separated by a line.

Period (browser picker)

Calendar

With data-kit-datepicker on the field (needs kit.js) the browser's picker gives way to a calendar that is the same everywhere. It is optional: without the attribute the field stays native, and without JavaScript the one with the attribute stays a normal type="date".

  • The field shows and accepts mm/dd/yyyy (the order follows the page's language: in Italian it is dd/mm/yyyy). You can also type it: the slashes are added by themselves and 3/5/26, 03.05.2026, 03052026, 2026-03-05 all work.
  • The value sent with the form is always yyyy-mm-dd, in a hidden field that takes the name: the server reads it without conversions.
  • It opens with the calendar button or the down arrow. On a phone you just tap the field (the keyboard does not appear).
  • The month title leads to the months, and the year title to the years: useful for birth dates.

On change the field's input and change events fire (so htmx's hx-trigger="change" works too) and kit:change with { value, display }: value in ISO, display as written in the field.

Limits and excluded days

min and max (or data-kit-min and data-kit-max) set the allowed range. Besides the ISO date they accept today and an offset in days: +30 is in thirty days, -7 a week ago. data-kit-disable excludes days of the week (mon… sun) and specific dates. Excluded days are visible but cannot be chosen; if the date is typed by hand the field is invalid (setCustomValidity, so the form does not submit) and gets the red border.

Range

data-kit-daterange on a container with two <input type="date"> (from, to). The calendar shows two months side by side, with a colored band between the two dates; while choosing the second one, hovering over the days shows a preview. You can also type the dates in the two fields. If "to" precedes "from" the field is invalid. The quick choices are on the left (on a phone they become a scrolling row above the calendar); data-kit-presets chooses which ones (none removes them).

Period
Value: 2026-11-01 → 2026-11-12

The available choices are today, yesterday, 7, 30, 90 (last N days), month, last-month, year, last-year (the old Italian names oggi, ieri, mese, mese-scorso, anno, anno-scorso still work). By default 7,30,month,last-month,year. Those that fall outside min and max are shortened, or disabled if they stay entirely outside. The kit:change event has { from, to }, and input and change fire on both fields.

Date and time

On a type="datetime-local" the calendar has hour and minute columns next to it. The field shows mm/dd/yyyy hh:mm and sends yyyy-mm-ddThh:mm, like the native field. "Done" closes. If you only choose the time, the date becomes today; if you only choose the day, the time is 00:00. data-kit-step="15" (minutes) limits the minutes to multiples of 15; the step attribute in seconds works too.

Time only

On a type="time" (or with data-kit-timepicker) you choose hours and minutes in two columns. You can also type 9, 9.30, 930. The value is hh:mm in 24 hours, the same as the native field. min and max count as times (09:00, 18:00).

Phone and touch

  • Below 576 px the calendar becomes a bottom sheet, full width, with a darkened backdrop and a "Close" button; the backdrop edge or Esc closes it. The page below does not scroll.
  • With a "coarse" pointer (fingers) days, months and hours are 44 px tall, even on a tablet.
  • The field does not open the keyboard (inputmode="none"): a tap opens the calendar. With a mouse it stays a numeric field to type in.
  • The field's text is at least 16 px, so iOS does not zoom the page.
  • The calendar is in the page's top layer (popover): no card, scrolling table or dialog clips it.
  • If you prefer the system picker for phones, do not add data-kit-datepicker and use the native field: its look is already the kit's.

With Django and htmx

The visible field has no name: the hidden one has it, and it contains the ISO date. So request.GET["dal"] and cleaned_data receive 2026-11-12, with no formats to configure.

# forms.py — format="%Y-%m-%d" lets the native field (without JavaScript) show the initial value
class PeriodForm(forms.Form):
    dal = forms.DateField(required=False, widget=forms.DateInput(
        format="%Y-%m-%d", attrs={"type": "date", "class": "kit-input", "aria-label": "From"}))
    al = forms.DateField(required=False, widget=forms.DateInput(
        format="%Y-%m-%d", attrs={"type": "date", "class": "kit-input", "aria-label": "To"}))
<form hx-get="{% url 'invoices' %}" hx-target="#results" hx-trigger="change">
  <div class="kit-daterange" data-kit-daterange>{{ form.dal }}{{ form.al }}</div>
</form>
  • With htmx put hx-get and hx-trigger="change" on the form (or a container), not on the single field: the hidden field is in the form and gets included. The change event fires after every choice, with the value already updated. On a single field, hx-include names the other one.
  • The fragments htmx inserts initialize by themselves (htmx:load); also with hx-swap="outerHTML" on the form.
  • With django-filter, DateFromToRangeFilter and RangeWidget(attrs={"type": "date", "class": "kit-input"}) produce two fields in a row, suited to kit-daterange.
  • A server error on a field: add aria-invalid="true" and the message in <small class="kit-danger">, as for the other fields.

JavaScript

const field = Kit.datepicker("#due");                    // returns { get, set, clear, open, close }
field.set("2026-12-31");                                  // without an event (set(v, true) fires it)
field.get();                                              // "2026-12-31"

const period = Kit.daterange("#period", { presets: ["today", "7", "month"] });
period.set({ from: "2026-11-01", to: "2026-11-12" });
period.get();                                             // { from, to }

Kit.date.parse("3/5/26");                                 // "2026-03-05" ("" if empty, null if not a date; the order depends on the language)
Kit.date.format("2026-03-05");                            // "03/05/2026"
Kit.i18n.add("en", { date: { t: { today: "Now" } } });    // texts and month names can be replaced (see Languages)

document.addEventListener("kit:change", (e) => {
  console.log(e.detail);                                  // { value, display } or { from, to }
});

Dates are ISO strings and calculations are done in UTC, so the browser's time zone never shifts a day. "Today" is the device's local date.

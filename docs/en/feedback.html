Alerts and progress

Alerts, status badges, progress bars, empty states and a welcome screen.

Alerts

A highlighted message inside the page: colored left border and soft background. Without a variant it is information; the others are -success, -warning, -danger and -neutral.

Imported invoices stay on your computer.
Import completed: 24 invoices added.
3 invoices are waiting for a receipt from the tax authority.
Unable to read the file: it is not a valid invoice.
Last updated: today at 09:41.

With an icon

Put a <svg class="kit-icon kit-alert-icon"> as the first child: the alert leaves room on the left and the icon takes the variant's color. Icons come from your SVG sprite; here i-info, i-ok, i-warn and i-error (you will find them in this documentation's sprite).

Imported invoices stay on your computer.
Import completed: 24 invoices added.
3 invoices are waiting for a receipt from the tax authority.
Unable to read the file: it is not a valid invoice.

For an important alert use role="alert" (it is read immediately by screen readers), for the others role="status".

With a title and a link

Deadline approaching You have until the 30th of the month. Go to the invoices to send.

Dismissible

A .kit-alert-close button with data-kit-dismiss removes the alert. The kit:dismiss event bubbles up from the container, if you need to know.

Saved. You can close this message.

Color is not enough on its own: the alert's text must explain what happened.

Badge

Status labels. Color conveys the outcome: green positive, yellow needs checking, red error, gray neutral.

Info Issued Received Error Neutral

Do not rely on color alone for meaning: the badge's text must be enough on its own.

Progress bar

Progress is the --kit-value variable (0–100%) on the inner element. Change it from JavaScript with el.style.setProperty("--kit-value", "40%").

Meter

A measure against a limit: space used, plan quota, score. It differs from the progress bar because it is not heading toward completion: the value is what it is, and the color says whether the level is fine (is-success), needs attention (is-warning) or is critical (is-danger). Without a state class the bar is in the accent color. As with the native <meter> element, it has role="meter" and its aria-valuenow, -min and -max; the accessible label is aria-label.

CSS only (fine for server-side rendering): the width is --kit-value and you choose the state. kit-meter-head puts name and value above the bar.

With kit.js just give the value and thresholds and the state is computed by itself. The attributes are data-kit-value, data-kit-min (0), data-kit-max (100), data-kit-warn and data-kit-danger, in the same unit as the value. By default higher is worse: from warn up it is orange, from danger up red, below it is green. With data-kit-good="high" (a score, a coverage) it reads the other way round: up to warn orange, up to danger red. Without thresholds it stays in the accent color. Meters inside a fragment inserted by htmx also set themselves up. Sizes: kit-meter-sm and kit-meter-lg.

Kit.meter(element, options) accepts the same things as options (value, min, max, warn, danger, good) and returns { set(value), value(), state() }; set() updates width, ARIA and color, state() gives "success", "warning", "danger" or null.

Do not rely on color alone for the level: also write the value (with kit-meter-head or next to the bar), so it is understood even without telling colors apart.

Spinner

A spinning ring, in the text color and as big as the font: inside a button or next to a sentence nothing else is needed. kit-spinner-sm and -lg change the size, kit-spinner-accent uses the accent color. Add role="status" and an aria-label, or text next to it, so that screen reader users know something is loading.

Skeleton

Placeholders with a moving shine, to reserve space while data arrives. Put aria-busy="true" on the container and aria-hidden="true" on the placeholders, which are purely decorative. Parts: kit-skeleton-text (a line of text, the last one shorter), -title, -circle and -block.

Full-screen progress

For a long operation (reading a folder, importing a file) that blocks the rest of the page. Kit.progress(text, options) opens a dialog with the text and the bar and returns { update(text, value), close() }. The value goes from 0 to 1; without a value (null) the bar runs by itself, for when you do not know how much is left. Esc and a click on the background do not close it: you close it with close(), or with onCancel a "Cancel" button appears (and Esc counts as Cancel). With delay (in ms) it appears only if the operation lasts longer than that, so quick operations do not flash.

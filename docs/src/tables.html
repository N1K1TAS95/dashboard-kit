Ordinamento

Con kit.js, data-kit-sort sulla tabella rende cliccabili le intestazioni: il primo clic ordina in modo crescente, il secondo decrescente, il terzo riporta l'ordine di partenza. L'intestazione riceve aria-sort (ascending, descending, none) e dentro si mette un bottone, quindi funziona anche da tastiera. Il tipo della colonna si riconosce dal contenuto: numeri in formato italiano (1.250,00, −310,00, 12 %, € 5), date (12/03/2026, 2026-03-12, con l'ora se c'è) e testo, confrontato senza badare a maiuscole e accenti e con i numeri «naturali» (FT-9 prima di FT-10). Le celle vuote o con solo un trattino vanno sempre in fondo; a parità di valore resta l'ordine di partenza. Un aria-sort="ascending|descending" scritto nell'HTML è l'ordinamento iniziale.

Più colonne

Con data-kit-sort="multi" si ordina anche per più colonne insieme: Shift + clic o Ctrl/⌘ + clic sull'intestazione la aggiunge come criterio successivo (e di nuovo la inverte, e poi la toglie), mentre un clic normale riparte da quella colonna sola. Il primo criterio è quello principale, gli altri decidono a parità; con più criteri accanto alla freccia compare il numero di priorità. Da tastiera, Shift + Invio sul bottone dell'intestazione. Provalo: Cliente, poi Shift + clic su Importo.

Filtro di testo

data-kit-filter="#id" su un campo di testo collega il campo alla tabella con quell'id: mentre si scrive restano le righe che contengono tutte le parole (in qualsiasi cella, senza badare a maiuscole e accenti). Se non resta nulla compare una riga «Nessun risultato» (data-kit-empty sulla tabella per cambiare il testo). L'ordine e il filtro lavorano insieme; l'evento è kit:filter con { query, count }.

Paginazione

data-kit-page="N" sulla tabella mostra N righe per volta e aggiunge sotto la barra kit-pagination: il conteggio («1–5 di 12»), i pulsanti precedente e successivo e i numeri di pagina con i puntini quando sono tanti. La pagina corrente ha aria-current="page", il conteggio è un'area aria-live e il focus resta sul bottone premuto. Funziona insieme a ordine e filtro: cambiando uno dei due si torna alla prima pagina, e il conteggio è quello delle righe filtrate. In stampa la barra non c'è e esce la pagina mostrata.

JavaScript

Gli attributi bastano nella maggior parte dei casi. Se le righe cambiano dopo il caricamento (una tabella riempita da una richiesta) si chiama api.refresh(); per il resto Kit.table(tabella, opzioni) fa tutto da codice e Kit.paginate(tabella, righe) è la scorciatoia per la sola paginazione. Entrambe restituiscono lo stesso oggetto.

const api = Kit.table("#fatture", { sort: true, size: 10, empty: "Nessuna fattura" });

api.sort(3, "descending");   // colonna (da 0) e direzione: "ascending", "descending" o "none"
api.sort([[2, "ascending"], [3, "descending"]]);   // più colonne (con data-kit-sort="multi")
api.filter("alfa");          // come scrivere nel campo di ricerca
api.page(2);                 // vai alla pagina 2; api.page() la legge
api.pageSize(25);            // righe per pagina; 0 = tutte
api.refresh();               // dopo aver aggiunto, tolto o cambiato delle righe
api.state();                 // { sort: { column, direction, criteria }, query, page, pages, size, total, count }

document.querySelector("#fatture").addEventListener("kit:page", (e) => {
  console.log(e.detail);     // { page, pages, size, total }
});

Intestazione agganciata

Di base le intestazioni (<th>) restano incollate sotto .kit-header mentre la pagina scorre. Dentro kit-table-wrap restano invece agganciate al bordo del riquadro, perché è lui a scorrere. La spaziatura delle celle si regola con --kit-row (verticale) e --kit-cell (orizzontale).

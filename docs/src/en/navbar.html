Basic navbar

The navbar is a .kit-header with the kit-navbar class. Inside go, in this order, the logo (kit-brand), the menu (kit-navbar-menu) with the list of items (kit-nav) and, if needed, actions on the right, and finally the button that opens the menu on small screens (kit-navbar-toggler).

With kit-navbar-expand-md the menu is inline from 768px up and, below that, it hides behind the three-line button. Try narrowing the window. The button has data-kit-nav with the menu's id: kit.js is needed.

Items

kit-nav-link is used on an <a> (or on a <button>). The current page is marked with aria-current="page" (or with the is-active class): besides the color, screen readers read it too. To disable an item there is aria-disabled="true" or the disabled attribute. Inside the item you can put an icon or a kit-badge.

Items with a dropdown menu

An item can open a menu: it is the same dropdown menu as for buttons (kit-dropdown, kit-pop, kit-opt), placed inside an <li>. The up and down arrows move through the items, Enter selects, Esc closes. In the collapsible menu the dropdowns open inline, below the item.

Search, theme and actions

After kit-spacer goes what sits on the right: a search field, the settings panel, a user menu. What you put inside kit-navbar-menu hides with the menu. What you put in kit-navbar-actions, after the menu and before the button, always stays visible: it is the right place for theme and user.

The order in the code matters: logo, menu, kit-navbar-actions, button. The collapsible menu is out of the flow, so on a small screen only the logo, actions and button remain on the bar.

Collapsible menu

On a small screen the menu drops below the bar, full width, and scrolls if it is taller than the window. Below, the navbar without kit-navbar-expand-*, so the button is always there.

Aligned with the content: kit-container

As with the normal header, put a container inside the navbar: the bar stays as wide as the window (with the background and border), but logo, items and actions align with the page content. The container becomes the navbar's inner row. The collapsible menu stays as wide as the window.

ClassEffect on the navbar
kit-containerCentered, with maximum width --kit-container-w. It follows the global switch data-layout="boxed|fluid": with fluid it fills the whole window, like the content.
kit-container-boxedAlways centered, whatever the switch.
kit-container-fluidAlways full width.
noneThe whole window, with only the header's side margin.

In the examples the maximum width is reduced to 36rem, just to show the difference; the dashed box is the container. The first is kit-container-boxed, the second kit-container-fluid.

The container goes inside the navbar and the page content (.kit-main) uses the same one: this way navbar and page stay aligned, even when the user changes width from the settings.

The collapsible menu (kit-navbar-menu) is positioned relative to the navbar, not to the container: that is why it stays full width.

Vertical list

kit-nav-col lays the items out in a column: for a side menu, or for a list of sections.

Accessibility

  • Put the list inside a <nav> with aria-label (if there is more than one on the page).
  • Items are real links and buttons: they can be reached with Tab and have a focus ring.
  • The menu button has an aria-label, because it contains only an icon.

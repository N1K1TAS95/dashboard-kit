Dialog

It uses the native <dialog> element: the browser handles focus, the Esc key and the darkened backdrop. The kit adds the style and two attributes: data-kit-open to open it, data-kit-close to close it. A click on the backdrop closes it.

The dialog is a card overlay: it has the same three parts (kit-card-head, kit-card-body, kit-card-foot), the same padding and the same border. If the content is tall, only the body scrolls; title and buttons stay visible. This also holds if the three parts are inside a <form> (<form method="dialog">). If instead the content is placed directly in the dialog, without kit-card-body, the whole dialog scrolls.

The width is chosen with a class: kit-dialog-sm (340px), no class (440px), kit-dialog-lg (700px, also kit-dialog-wide), kit-dialog-xl (960px) and kit-dialog-full (the whole window minus the margins). For your own value set --kit-dialog-w: on a single dialog (style="--kit-dialog-w: 520px") or on all of them (:root { --kit-dialog-w: 520px }). On narrow screens the dialog never goes outside the window.

Drawer

A dialog that slides in from an edge of the window: for a detail, an advanced filter or a long form, when you want to keep the page in view. It is the same <dialog>, with the same parts, the same attributes (data-kit-open, data-kit-close) and the same Esc, backdrop click and focus; you only add the kit-drawer class. By default it comes from the right; kit-drawer-left, kit-drawer-top and kit-drawer-bottom change the side. On a narrow screen it takes the full width.

Asking for confirmation

A dialog with "Confirm" and "Cancel" interrupts whoever is working, and if it appears too often people learn to press "Confirm" without reading. It is better to choose based on how serious the mistake would be.

If the action…Use
can be undone (archiving, moving, deleting with a trash)Undo: the action runs immediately and the toast offers "Undo"
cannot be undone (deleting forever, sending, paying)Confirm with Kit.confirm or data-kit-confirm
is very serious or concerns a lot of data (deleting an archive)Confirm by typing the name

In any case: write the precise verb on the confirm button ("Delete 12 invoices", not "OK"), and say in the text what happens.

Kit.confirm

Kit.confirm(question, options) opens the dialog by itself, without HTML, and returns a promise: true if the user confirms, false with "Cancel", Esc or a click on the backdrop. With danger: true the button is red and focus starts on "Cancel", so an absent-minded Enter does no harm; without it, focus is on "Confirm".

The text is always plain text, never HTML: you can also pass a name entered by the user. The dialog is a <dialog> with role="alertdialog": Tab stays inside, Esc cancels and on closing focus returns to the button that opened it.

Typing the name

For truly irreversible actions, type asks to write a text (usually the name of what is being deleted): until it matches, "Confirm" stays disabled. Case matters; spaces at the edges do not. Enter in the field confirms, if the text is right.

Without JavaScript: data-kit-confirm

Put data-kit-confirm="Question?" on a button, a link or a <form>: the click (or the form submit) opens the dialog and, only if the user confirms, the action proceeds as if nothing had been in between. The confirmation runs before your click handlers, which only fire after the "yes". The other options are attributes: data-kit-confirm-text, -ok, -cancel, -danger (no value) and -type.

Undo instead of asking

For actions that can be undone, asking first is the worst choice: it slows everyone down to protect a few. Kit.undo does the opposite: the interface changes immediately and a toast with a time bar offers "Undo". When the time runs out (or the toast closes, or the page is left) onCommit runs, the real and final action; with "Undo" onUndo runs and onCommit never does.

Options: onUndo, onCommit, duration (default 6000 ms), label (default "Undo"), type and position as in toasts. It returns { undo(), commit() } to decide from code. If onCommit has to reach a server, remember that when the page closes the browser may interrupt the request: use fetch with keepalive: true.

Animation

All kit-dialogs appear and disappear with a short fade (0.18 s), a slight upward slide and the backdrop darkening. It turns itself off with prefers-reduced-motion. A recent browser is needed (Chrome 117, Safari 17.4, Firefox 129): in the others the dialog appears and disappears without animation, but works just the same.

Pop-up menu

.kit-pop is a panel that can be used on its own, for any menu: a row's actions, a button's items, the theme selector. A button with data-kit-toggle="#id" opens the indicated .kit-pop (inside a .kit-dropdown, which positions it under the button). It closes with Esc, by clicking outside or by choosing an item; the arrow keys move through the items, Enter activates them.

Tooltip

A short hint on any element, with CSS only: the data-kit-tip attribute is enough. It appears on mouse hover (after a short wait) and on keyboard focus; with kit.js the Esc key hides it. The mouse can reach the tooltip without it disappearing.

Received A link

Position

data-kit-tip-pos chooses the side: top (default), bottom, left, right.

The tooltip is not a way to provide a label: an icon-only button must still have aria-label. Do not put essential information, links or buttons in it, because on touch and for screen reader users it may not appear. A disabled button does not receive the mouse: put the tooltip on a <span> that contains it.

A container with hidden or scrolling overflow (for example .kit-table-wrap) clips the tooltip: in that case choose a side that stays inside the container.

Toast

A short message that appears at the bottom and disappears by itself. It is shown from JavaScript with Kit.toast("text"); several toasts stack, up to six at a time. The neutral toast is inverted relative to the theme (dark on light, light on dark), so it always stands out from the content; colored ones fill the whole background.

Types, title and icon

The type option (info, success, warning, danger) colors the whole toast and adds the icon, if the page has the icons sprite (kit-icons.js); title adds a title. warning and danger toasts are announced immediately by screen readers (role="alert"), the others discreetly.

Action and closing

With action the toast has a button (typically "Undo") and stays visible until you use it or close it with the ×. duration is in milliseconds (default 4000); with 0 the toast does not disappear by itself. A bar at the bottom of the toast shows how long is left before closing (remove it with progress: false). The time stops while the mouse or focus is on the toast, and the bar goes back to full: when you leave, the countdown restarts from the beginning. Kit.toast returns an object with close() to close it from code, and Kit.toast.clear() closes them all.

Position

position chooses where it appears: bottom (default), top, bottom-start, bottom-end, top-start, top-end. The corners are the most used in dashboards, because they do not cover the central content.

Settings panel

A single menu for the user's preferences: theme (automatic, light, dark), text size and content width, plus "Reset". It is a pop-up menu with the kit-settings class, made of kit-seg groups whose buttons use the kit.js attributes you already know (data-kit-theme-set, data-kit-fs-set, data-kit-layout-set). Unlike a normal menu it stays open after each choice, so you can change several things in a row; it closes with Esc or by clicking outside. All choices are remembered. The rows are independent: remove the ones you do not need. data-kit-reset (or Kit.reset()) brings everything back to the starting value: system theme, normal text, the width written in the HTML. It is the "Settings" menu at the top right of these pages.

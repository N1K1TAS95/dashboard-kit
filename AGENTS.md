# AGENTS.md

Instructions for coding agents working **on this repository** (Dashboard Kit). If you only want to *use* the kit in another project, read [`llms.txt`](llms.txt) instead: it lists the documentation and the machine-readable files.

## What this is

A CSS framework (`dist/kit.css`) with optional JavaScript (`dist/kit.js`) and an SVG icon sprite (`dist/kit-icons.js`), used with server-rendered pages (Django + htmx). No build step, no dependencies, no package manager: the files in `dist/` are written by hand and copied as they are.

## Rules of the framework

- Every class starts with `kit-`; every data attribute with `data-kit-`; every custom property with `--kit-`. Never add unprefixed names.
- Colors, sizes and radii come from the `--kit-*` tokens in `:root` of `kit.css`. Colors use `light-dark()`, so a component never needs separate light and dark rules. Do not hard-code colors or pixel sizes where a token exists.
- Sizes are in `rem` (they follow `--kit-fs`), except hairlines and breakpoints.
- Components must work on fragments inserted by htmx: `kit.js` initializes on `DOMContentLoaded` and on `htmx:load` through `Kit.init(root)`. Do not rely on one-time setup of the whole document. Where it makes sense, offer a CSS-only version for server rendering.
- Accessibility is part of the component: keyboard use, focus return, `aria-*`, `prefers-reduced-motion`, 44px touch targets on phones.
- `kit.js` is optional. A component that can work without it (e.g. `<details>` accordion) must.
- Do not invent classes in examples or docs: check that they exist in `dist/kit.css` (`kit-components.json` lists those used in the documentation).
- The grid block of `kit.css` is generated by `tools/gen-grid.py`: change the script, not the generated block.

## Internationalization

- English is the default language; only `en` and `it` exist. Text in `kit.js` goes through `Kit.i18n` (messages follow `<html lang>`); do not hard-code user-facing strings.
- Documentation, README, CHANGELOG and SECURITY exist in both languages (`*.it.md` for Italian). Keep both in step when you change one.
- Identifiers, class names and code are the same in both languages. Code comments in `dist/` and `tools/` are still partly Italian; new comments may be in either language.

## Documentation

- **Never edit `docs/en/*.html` or `docs/it/*.html` by hand.** They are generated. Edit the content in `docs/src/<lang>/<page>.html` (only the page content, with the lines `<!--title: …-->` and `<!--desc: …-->`) and run:

  ```
  python3 tools/gen-docs.py
  ```

- The generator adds header, menu, section index, previous/next links, the token and snippet tables, the icon list, the search index (`docs/<lang>/search-index.js`) and the SRI hashes. It also writes `llms.txt`, `llms-full.txt` and `kit-components.json` in the repository root from the **English** pages: these three are generated too.
- Section ids (`<h2 id>`, `<h3 id>`) are English and are also the anchors other pages link to. When you rename one, fix the links in every page of both languages.
- An example is `<div class="doc-demo">…</div>`: the code shown below it is generated from its markup. Use `data-doc-nocode` when you provide your own `<pre>`.
- Add a page: create `docs/src/it/name.html` and `docs/src/en/name.html`, then add it to `NAV_IT` and `NAV_EN` in `tools/gen-docs.py`.
- The two example pages are static files in `docs/src/examples/<lang>/`, copied by the generator (`docs/en/dashboard*.html`, `docs/it/dashboard*.html`); their shared `dashboard.css` and `dashboard.js` live in `docs/`.
- To check a page, open it in a browser (or headless Chrome with `--enable-logging=stderr`) and make sure there are no console errors; check links and anchors in both `docs/en` and `docs/it`.

## Adding or changing a component

In this order:

1. CSS in `dist/kit.css`.
2. JavaScript in `dist/kit.js`, if needed (including `Kit.i18n` messages in both languages).
3. Documentation page, in both languages, with examples.
4. VS Code snippets in `vscode/dashboard-kit.code-snippets` (English; the Italian descriptions for the docs table are in `tools/snippets.it.json`).
5. An entry under "Unreleased" in `CHANGELOG.md` (English only).
6. Regenerate the docs, then, for a release, the SRI hashes.

## Release

Docs are published from `main` (GitHub Pages) together with a release, never before it.

1. Update the version in the header comments of `dist/kit.css` and `dist/kit.js`, and `VERSION` in `tools/gen-docs.py`.
2. Run `./sri.sh` to recompute the SRI hashes; update the links in `README.md` and `README.it.md`.
3. Run `python3 tools/gen-docs.py`.
4. Commit, tag `v<version>`, push the commit and the tag. jsDelivr serves the files from the tag, so the hashes in the README only hold for that tag.

Breaking changes (a different default language, a renamed class) bump the minor version while the major is 0.

## Git

- Commit only when asked. Messages are in Italian, in the form "Area: what changed".
- Do not commit generated output separately from the source that produced it.
